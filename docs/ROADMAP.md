# 产品路线与开源项目调研结论

这份路线刻意把“可爱的桌宠”和“可靠的小管家”拆开推进。功能是否加入以不打扰她的日常使用为准，而不是以功能数量为准。

## 下一版优先级

### P0：先让桌宠像桌宠

1. 已完成：拆成两个窗口——一个只保留 BA仔和打开按钮的透明悬浮窗，一个按需打开的控制/聊天面板。
2. 已完成基础托盘：打开、暂时隐藏、居中找回和退出；关闭面板默认只收起。锁定位置与静音将在有音效/游走后加入。
3. 已完成：记住位置、皮肤和三档尺寸，并提供“放回屏幕中央”；是否置顶仍待设置页开放。
4. 待完成：安静模式 / 减少动画 / 不自动游走三个开关，默认不主动遮挡工作。

### P1：再加动作状态机

动作是独立的状态机，不直接写在聊天逻辑里。最小状态集：`idle`、`talk`、`focus`、`celebrate`、`kick`、`sleep`、`walk`。每个状态有时长、冷却时间和可中断规则。第一批自动行为只在空闲时触发，且始终可关闭。

### P2：小管家能力

1. AI 先提出“要记住 / 要新建日程”的卡片，用户确认后才写入本地。
2. 加本地备份与导出（SQLite 副本或 JSON），恢复前先预览。
3. Excel 导入支持更多日期格式、选择工作表、显示无法解析的行。
4. 番茄钟完成可获得轻量装饰或台词，不做强迫式打卡。

## 从相近开源项目吸收的做法

| 观察 | BA仔的决定 |
| --- | --- |
| 角色包使用 `sprite.png + preview.png + character.json`，动作与角色素材解耦。 | 现在的 PNG 皮肤先按统一目录组织；做逐帧动画时升级为每套皮肤一个动作清单。 |
| 真正的桌宠常把透明宠物窗与设置窗口分开。 | P0 拆窗；控制页不拥有任意移动桌宠窗口的权限。 |
| 托盘、可选开机启动、静音和点击穿透让桌宠不打扰工作。 | P0 加托盘和安静模式；点击穿透默认关闭，避免误操作。 |
| 自动游走、心情、音效和奖励很容易失控。 | 行为必须状态机化、带冷却和总开关；奖励只辅助番茄钟。 |
| 透明窗口在 Windows 多屏、高 DPI、全屏软件下最容易出问题。 | 每次发布至少手测 100%/150% 缩放、双屏、全屏视频和“重置位置”。 |
| 未签名的 Windows 安装包会遇到 SmartScreen。 | 首次给她安装可采用自己构建的安装包；若将来公开分发，再考虑代码签名。 |

## 发布前的开源检查

- 由项目拥有者决定许可证（MIT、GPL 等）；在未决定前不要宣布“已公开许可”。
- 删除任何真实 API 密钥、数据库、聊天记录和绝对个人路径。
- 对非代码素材保留来源和许可说明；本项目的 BA仔形象仅用于这份定制礼物。
- 发布前运行 `npm run verify`，并从 Windows 安装包做一次干净安装测试。
