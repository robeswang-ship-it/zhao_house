# BA仔维护交接说明

这份说明刻意不绑定 Codex。无论使用什么本地 Agent，都应在改代码前完整阅读本文件和 `ARCHITECTURE.md`。

## 给维护 Agent 的起始任务

```text
你在维护 BA仔 · 小猫管家。请先阅读 README.md、docs/ARCHITECTURE.md 和本文件。
先说明你准备改动的文件、用户数据和安全影响；不要把 API 密钥写入任何代码或配置。
实施后运行 npm run verify，并简要报告改动、验证结果和仍未覆盖的 Windows 手工测试。
除非用户明确要求，不要删除本地数据库、聊天记忆、日程或皮肤资产。
```

## 不可破坏的约束

- 本地优先：日程、记忆、番茄钟与聊天记录默认只在设备上保存。
- 密钥隔离：只能通过原生凭据库读写 API 密钥；前端不得长期保存明文。
- 更新链完整性：更新私钥和 GitHub 发布 Token 只能存在于项目拥有者的安全备份与 CI Secrets；绝不写入项目、安装包、日志或用户电脑。
- AI 有边界：AI 可以建议和总结；写日程、写记忆、发送外部请求必须有清楚的用户动作或确认。
- 不干扰：桌宠默认不能遮挡点击、制造高频弹窗或在深夜主动打扰；自动游走必须可关闭。
- 可恢复：涉及数据库结构、导入或批量修改时，先做备份或提供撤销方案。

## 修改后的最低验证

```bash
npm run verify
```

另外在 Windows 真机检查：启动时只显示 BA仔悬浮窗；点小猫和点托盘左键都能打开面板；面板右上角 × 只收起而不退出；拖动后重启仍保留位置、托盘“居中”可找回；皮肤切换后重启仍保留；系统缩放为 100% 与 150% 时不模糊；Excel 导入预览正常；AI 密钥不会显示在界面或日志中。

## 交接时要记录什么

在 PR、提交说明或给下一位 Agent 的消息中写清楚：改了哪些文件；是否触碰用户数据；是否新增权限或网络请求；跑过哪些自动检查；还需要用户在 Windows 上确认什么。
